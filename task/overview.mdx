## 和工具接口的区别

Hub 有两种接口：任务接口（本页，`/mcp/task`）是默认接法，顺序由服务端把着，每一步交回候选，下单前必停一次确认；零售只在任务接口。工具接口（`/mcp`）把业务接口直接交给你，适合要自己编排每一步的开发者，说明在 [Hub 文档中心](https://hub.clawdot.net/#/docs)。本站「外卖MCP」「跑腿MCP」两个 tab 是更早的直连接法，不再更新。

## 一单怎么走

![](/images/task/10-task.png)

### 流程描述

任务接口把一单收成一个 task：先 `create_task` 开 task（必带 `idempotency_key`），拿到 `task_id`；之后每次返回的 `next_action` 都写着下一步调哪个工具、哪个动作，接入方照着一组一组调外卖、跑腿或零售的分组工具，每次都带 `task_id`。外卖是定地址 → 选店选菜 → 加购与预览 → 确认下单 → 查单；跑腿是两端地址 → 物品与运力 → 确认下单 → 查单与预检取消 → 确认取消；零售是授权 → 选商品 → 地址 → 结算 → 确认下单 → 查单与售后。顺序由服务端把着：跳步、乱序的调用直接拒，并指回该回去的那一步。

每一步把候选交回来（`next_action.options[]`，每项带 `ref`），用户挑中哪一项就把它的 `ref` 原样传回；地址、购物车、确认页这些句柄都留在服务端，接入方不用拼参数。三类能力的工具都在 `/mcp/task` 这一个地址上；只接一个能力也可以连它的分能力地址（见 [接入与授权](/task/connect#分能力地址)）。

真正花钱前必停一次：外卖的 `food_cart` · `preview` 出确认页，把实付金额、店铺、送到哪摆出来，唯一那一项的 `ref` 就是 `confirm_ref`，用户明确同意后才交给 `food_place_order`。下单、取消这种不可逆的一步只认确认页给的 `confirm_ref`，金额只信确认页的数。

### 说明

- 单笔金额默认不设上限；按接入方设了上限时，超限的单下不了，返回里说明原因
- task 按「接入方 + 用户」隔离：用户以票为准
- create_task、fork_task 必带 idempotency_key：超时重试带同一个，回的是原来那个 task
- 状态 `indeterminate`，不知道成没成：下单或取消的请求发出去了，但没拿到确定结果。**既不要重试，也不要当失败另开一单**；按 next_action 去查单那一组的 list，请用户核对最近的订单。
- 工具、返回的形状、状态与拒绝码见 [返回结构与枚举](/task/response) 和各工具页。
