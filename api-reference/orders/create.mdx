## POST /orders/create

用一次预览返回的 `preview_id` 与 `confirmation_token` 正式下单。下单成功后返回平台订单 ID `order_id`、订单状态 `status`、应付金额 `payable_price`，以及（需支付时的）支付动作 `payment_action`。

<Note>
  **下单链路**：`/shops/search` 得 `shop_id` + `cart_id` → `/shops/menu` 选商品 → `/cart/quote` 算价得 `quote_id` → `/addresses/select` 得 `address_id` → `/orders/preview` 得 `preview_id` + `confirmation_token` → **`/orders/create`** 得 `order_id` + `payment_action`。`preview_id` 与 `confirmation_token` 必须来自**同一次** `/orders/preview` 调用，原样回传，不可自造或混用。
</Note>

<Note>
  本接口**幂等**：以 `confirmation_token` 为幂等键。幂等指纹只比对 `preview_id` + `confirmation_token` + `payment_method` 三项（**不含** `callback_url`）。用相同 `confirmation_token` 重复调用时：若 `preview_id`、`payment_method` 与首次一致，返回首次的结果；若任一与首次不一致，则返回 `IDEMPOTENCY_CONFLICT`。同一令牌只能下一单——再次下单需重新走 `/orders/preview` 取新令牌。注意：仅改 `callback_url`（其余三项不变）不算冲突，会命中重放并**重新注册一次轮询**（回调因此可能多次送达）。
</Note>

### 请求头

| 名称 | 必填 | 说明 |
|------|------|------|
| `Authorization` | 是 | `Bearer clw_...`（Agent 的 API Key）|
| `X-Consent-Grant-Id` | 是 | 用户授权 ID（`cg_...`）|
| `Content-Type` | 是 | `application/json` |

### 请求体

```json
{
  "preview_id": "<来自 /orders/preview>",
  "confirmation_token": "<来自 /orders/preview>",
  "payment_method": null,
  "callback_url": "https://your-app.example.com/clawdot/callback"
}
```

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| `preview_id` | string | 是 | — | 预览 ID（来自 `/orders/preview`，原样回传）|
| `confirmation_token` | string | 是 | — | 确认令牌（来自 **同一次** `/orders/preview`，原样回传）；同时作为幂等键 |
| `payment_method` | string \| null | 否 | `null` | 支付渠道；不传则用默认渠道 |
| `callback_url` | string \| null | 否 | `null` | 支付状态回调地址（绝对 http(s) URL）；填写后网关侧轮询订单状态，脱离未支付态即向该地址 POST 一次回调（见下）|

<Warning>
  请求体**不接受未定义字段**（`extra=forbid`），多传会返回 422。
</Warning>

**`callback_url` 说明：** 必须是绝对的 `http`/`https` URL，禁止指向回环 / 内网 / 链路本地等地址。填写后网关每隔约 2 秒轮询订单状态，一旦订单脱离未支付态（`created` / `pending_payment`），向该地址 POST 一次回调。轮询窗口约 **15 分钟**（`POLL_WINDOW_SECONDS = 15 * 60`）；窗口耗尽仍未支付则按 `timeout` 收尾，确保任务必然终止。回调 body 固定为以下 6 个键：

```json
{
  "event": "order_payment",
  "order_id": "ord_...",
  "ispay": "success",
  "status": "paid",
  "status_text": "已支付",
  "consent_grant_id": "cg_..."
}
```

| 字段 | 说明 |
|------|------|
| `event` | 固定为 `order_payment` |
| `order_id` | 平台订单 ID |
| `ispay` | 支付结果枚举（见下）|
| `status` | 回调时刻的订单状态枚举（与响应 `status` 同一枚举）|
| `status_text` | `status` 对应的中文文案（如 `已支付` / `已取消`）|
| `consent_grant_id` | 该订单所属的用户授权 ID，供调用方校验匹配 |

**`ispay` 枚举（共 4 值）：**

| 值 | 含义 | 触发的订单状态 |
|------|------|------|
| `success` | 已进入支付链路 | `paid` / `preparing` / `delivering` / `completed` / `refunded` |
| `closed` | 取消或关闭 | `cancelled` / `failed` |
| `timeout` | 约 15 分钟轮询窗口耗尽仍未支付（调用方不悬空）| 窗口结束时仍为 `created` / `pending_payment` |
| `unknown` | 授权被撤销 / 轮换，或订单引用失效，网关无法再代查 | — |

回调为**至少一次**送达；幂等重放 `create_order` 会重新注册轮询（回调可能多次送达）。回调失败不影响订单结果——不传 `callback_url`（或想兜底）时请自行轮询 `/orders/{order_id}`。

### 响应

```json
{
  "order_id": "ord_8c1d...",
  "status": "pending_payment",
  "payable_price": 1500,
  "payment_action": {
    "action_id": "act_3f9a...",
    "action_type": "open_h5",
    "action_url": "https://...",
    "expires_at": "2026-06-16T12:30:00+00:00"
  },
  "callback_registered": true
}
```

<Warning>
  金额字段 `payable_price` 单位为**分（整数）**，不是元。例如 `payable_price: 1500` 表示 ¥15.00。
</Warning>

| 字段 | 类型 | 说明 |
|------|------|------|
| `order_id` | string | 平台订单 ID（`ord_` 前缀），传给 `/orders/{order_id}` 查状态 |
| `status` | string | 订单状态枚举（见下）|
| `payable_price` | integer | 应付金额（分）|
| `payment_action` | object \| null | 支付动作；需支付时返回，否则为 `null` |
| `payment_action.action_id` | string | 动作 ID（`act_` 前缀）|
| `payment_action.action_type` | string | 动作类型，当前为 `open_h5`（打开 H5 支付页）|
| `payment_action.action_url` | string | 支付页 URL，引导用户完成支付 |
| `payment_action.expires_at` | string | 动作过期时间（ISO 8601，UTC）；有效期约 30 分钟 |
| `callback_registered` | boolean | 是否已注册支付回调（即请求是否带了有效 `callback_url`）|

**`status` 枚举：** `created`（订单已创建）、`pending_payment`（待支付）、`paid`（已支付）、`preparing`（商家备餐中）、`delivering`（配送中）、`completed`（已完成）、`cancelled`（已取消）、`failed`（下单或履约失败）、`refunded`（已退款）。

### 错误码

| HTTP | code | 说明 |
|------|------|------|
| 401 | `CONSENT_GRANT_REQUIRED` | 缺少 `X-Consent-Grant-Id` |
| 401 | `CONSENT_GRANT_INVALID` | 用户授权无效 |
| 401 | `CONSENT_GRANT_EXPIRED` | 用户授权已过期，需重新授权 |
| 403 | `CAP_NOT_BOUND` | 该 Agent 未开通对应能力 |
| 403 | `CONSENT_GRANT_WRONG_CAP` | 该授权属于其它能力 / 提供方 |
| 400 | `PUBLIC_REFERENCE_INVALID` | `preview_id` / `confirmation_token` 无效或过期、两者不匹配（非同一次预览），或 `callback_url` 不合法 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同一 `confirmation_token` 重复调用，但 `preview_id` 或 `payment_method` 与首次不一致；需重新预览取新令牌 |
| 422 | （参数校验）| 请求体字段类型 / 必填 / 未定义字段（`extra=forbid`）违规；REST 返回 FastAPI 默认 422 结构（非 `{error:{code}}`）|
| 500 | `ORDER_FAILED` | 订单创建失败；重新预览后重试 |
| 502 | `ELEME_ERROR` | 上游下单 API 错误；稍后重试 |

完整错误码见 [错误处理](/gateway/error-handling)。

### 示例

```bash
curl -X POST "http://eleme-gateway.hicaspian.com/api/v1/orders/create" \
  -H "Authorization: Bearer clw_your_api_key" \
  -H "X-Consent-Grant-Id: cg_your_consent_grant" \
  -H "Content-Type: application/json" \
  -d '{
    "preview_id": "<来自 /orders/preview>",
    "confirmation_token": "<来自 /orders/preview>"
  }'
```
