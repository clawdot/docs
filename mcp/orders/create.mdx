## create_order

用一次预览返回的 `preview_id` 与 `confirmation_token` 正式下单。下单成功后返回平台订单 ID `order_id`、订单状态 `status`、应付金额 `payable_price`，以及（需支付时的）支付动作 `payment_action`。

<Note>
  **下单链路**：`search_shops` 得 `shop_id` + `cart_id` → `get_shop_menu` 选商品 → `quote_cart` 算价得 `quote_id` → `select_address` 得 `address_id` → `preview_order` 得 `preview_id` + `confirmation_token` → **`create_order`** 得 `order_id` + `payment_action`。`preview_id` 与 `confirmation_token` 必须来自**同一次** `preview_order` 调用，原样回传，不可自造或混用。
</Note>

<Note>
  本工具**幂等**：以 `confirmation_token` 为幂等键。幂等指纹比对 `preview_id` + `confirmation_token` + `payment_method` 三项，外加 `require_phone_verify` 是否为 `true`（**不含** `callback_url`）。用相同 `confirmation_token` 重复调用时：若这几项与首次一致，返回首次的结果；若任一与首次不一致，则返回 `IDEMPOTENCY_CONFLICT`。同一令牌只能下一单——再次下单需重新走 `preview_order` 取新令牌。注意：仅改 `callback_url`（其余三项不变）不算冲突，会命中重放并**重新开始一轮状态跟踪**（回调因此可能多次送达）。
</Note>

### 参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| `consent_grant_id` | string | 是 | — | 用户授权 ID（`cg_` 前缀，来自 `verify_user_bind`），标识已授权用户 |
| `preview_id` | string | 是 | — | 预览 ID（来自 `preview_order`，原样回传）|
| `confirmation_token` | string | 是 | — | 确认令牌（来自 **同一次** `preview_order`，原样回传）；同时作为幂等键 |
| `payment_method` | string \| null | 否 | `null` | 支付渠道；不传则用默认渠道 |
| `callback_url` | string \| null | 否 | `null` | 订单状态回调地址（绝对 http(s) URL）；填写后这笔单每次状态变化都会向该地址 POST 一条事件（见下）|
| `require_phone_verify` | boolean | 否 | `false` | 为 `true` 时，这笔单的支付/详情链接打开后先要求输入下单手机号后 4 位确认本人，输对才进入订单页（见下）|

**`require_phone_verify` 说明：** 传 `true` 后，这笔订单的所有链接——本次返回的 `payment_action.action_url`，以及之后 `get_order_status` / `list_orders` 给出的 `detail_url`——打开时都会先出现一个「确认本人」页，输入下单手机号后 4 位，输对才进入订单页。输对一次后，同一浏览器 24 小时内再打开不用重输；连错 5 次后这笔单的链接锁定 24 小时。适合链接会经过聊天转发、担心发错人的场景。是否开启在下单时确定，之后不可更改；不传或 `false` 时链接与以往完全一样。

**`callback_url` 说明：** 必须是绝对的 `http`/`https` URL，禁止指向回环 / 内网 / 链路本地等地址。填写后，这笔订单**每次状态变化都会向该地址 POST 一条事件**，直到订单结束（`completed` / `cancelled` / `failed` / `refunded`）。查状态的频率是：未支付时约 2 秒一次，已支付后约 30 秒一次。订单满 2 小时仍未结束时，会推送一条 `timeout` 事件后停止，调用方不会一直等下去。

回调 body：

```json
{
  "event": "order_status",
  "order_id": "ord_...",
  "seq": 3,
  "status": "delivering",
  "previous_status": "preparing",
  "status_text": "配送中",
  "event_at": "2026-08-26T12:34:56+08:00",
  "consent_grant_id": "cg_..."
}
```

| 字段 | 说明 |
|------|------|
| `event` | `order_status`；支付成败那一条为 `order_payment`（见下）|
| `order_id` | 平台订单 ID |
| `seq` | 这笔单的事件序号，从 1 连续递增 |
| `status` | 本次变成的状态（枚举见下）|
| `previous_status` | 上一条事件的状态；首条为 `null` |
| `status_text` | `status` 对应的中文文案（如 `配送中`）|
| `event_at` | 事件发生时间（ISO 8601，北京时间）|
| `consent_grant_id` | 该订单所属的用户授权 ID。**极少数情况下会缺席**（服务重启后恢复跟踪的订单取不到该值），请按 `order_id` 匹配订单 |

**`status` 枚举（共 8 值）：**

| 值 | 含义 |
|------|------|
| `pending_payment` | 待支付 |
| `paid` | 已支付 |
| `preparing` | 商家备餐中 |
| `delivering` | 配送中 |
| `completed` | 已完成（结束）|
| `cancelled` | 已取消（结束）|
| `failed` | 下单或履约失败（结束）|
| `refunded` | 已退款（结束）|

<Note>
订单创建成功这件事不会单独推一条事件——`create_order` 的返回本身就是凭据。第一条事件通常是 `pending_payment`。
</Note>

**支付成败那一条额外带两个字段**，格式与旧版回调完全一致，已有的接收逻辑无需改动：

```json
{
  "event": "order_payment",
  "ispay": "success",
  "...": "其余字段同上"
}
```

| `ispay` | 含义 |
|------|------|
| `success` | 已进入支付链路 |
| `closed` | 取消或关闭 |
| `timeout` | 订单满 2 小时仍未结束 |
| `unknown` | 授权被撤销 / 轮换，网关无法再查该订单 |

**用 `seq` 自查有没有漏收：** 同一笔订单的 `seq` 从 1 连续递增。若你收到 1、2、4，说明第 3 条没送到，调 `get_order_status` 补查当前状态即可。

**去重：** 回调为**至少一次**送达，同一条可能重复到达，请按 `(order_id, seq)` 去重。

投递失败只重试三次（间隔 1 / 2 / 4 秒），之后不再补发，但不影响订单本身。不传 `callback_url` 则一条都不推，请自行调用 `get_order_status` 查询。

### 返回

```json
{
  "order_id": "ord_8c1d...",
  "status": "pending_payment",
  "payable_price": 1500,
  "payment_action": {
    "action_id": "act_3f9a...",
    "action_type": "open_h5",
    "action_url": "https://...",
    "expires_at": "2026-06-16T12:30:00+00:00"
  },
  "callback_registered": true
}
```

<Warning>
  金额字段 `payable_price` 单位为**分（整数）**，不是元。例如 `payable_price: 1500` 表示 ¥15.00。
</Warning>

| 字段 | 类型 | 说明 |
|------|------|------|
| `order_id` | string | 平台订单 ID（`ord_` 前缀），传给 `get_order_status` 查状态 |
| `status` | string | 订单状态枚举（见下）|
| `payable_price` | integer | 应付金额（分）|
| `payment_action` | object \| null | 支付动作；需支付时返回，否则为 `null` |
| `payment_action.action_id` | string | 动作 ID（`act_` 前缀）|
| `payment_action.action_type` | string | 动作类型，当前为 `open_h5`（打开 H5 支付页）|
| `payment_action.action_url` | string | 支付页 URL，引导用户完成支付；下单时传了 `require_phone_verify: true` 的订单，打开后先要求输入下单手机号后 4 位确认本人 |
| `payment_action.expires_at` | string | 动作过期时间（ISO 8601，UTC）；有效期约 30 分钟 |
| `callback_registered` | boolean | 是否已注册支付回调（即请求是否带了有效 `callback_url`）|

**`status` 枚举：** `created`（订单已创建）、`pending_payment`（待支付）、`paid`（已支付）、`preparing`（商家备餐中）、`delivering`（配送中）、`completed`（已完成）、`cancelled`（已取消）、`failed`（下单或履约失败）、`refunded`（已退款）。

### 错误码

| code | 说明 |
|------|------|
| `CONSENT_GRANT_REQUIRED` | 缺少用户授权（未传 `consent_grant_id`）|
| `CONSENT_GRANT_INVALID` | 用户授权无效 |
| `CONSENT_GRANT_EXPIRED` | 用户授权已过期，需重新授权 |
| `CAP_NOT_BOUND` | 该 Agent 未开通外卖能力 |
| `CONSENT_GRANT_WRONG_CAP` | 授权属于其它能力 / 服务商 |
| `PUBLIC_REFERENCE_INVALID` | `preview_id` / `confirmation_token` 无效或过期、两者不匹配（非同一次预览），或 `callback_url` 不合法 |
| `IDEMPOTENCY_CONFLICT` | 同一 `confirmation_token` 重复调用，但 `preview_id`、`payment_method` 或 `require_phone_verify` 与首次不一致；需重新预览取新令牌 |
| `ORDER_FAILED` | 订单创建失败；重新预览后重试 |
| `ELEME_ERROR` | 上游下单 API 错误；稍后重试 |

完整错误码见 [错误处理](/gateway/error-handling)。

### 调用示例

```json
{
  "name": "create_order",
  "arguments": {
    "consent_grant_id": "cg_your_consent_grant",
    "preview_id": "<来自 preview_order>",
    "confirmation_token": "<来自 preview_order>"
  }
}
```

链接需先确认本人时：

```json
{
  "name": "create_order",
  "arguments": {
    "consent_grant_id": "cg_your_consent_grant",
    "preview_id": "<来自 preview_order>",
    "confirmation_token": "<来自 preview_order>",
    "require_phone_verify": true
  }
}
```
