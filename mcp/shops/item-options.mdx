## get_item_options

一次**批量**拉取多个商品的**全量**规格候选（`sku_options`），**每个规格条目内嵌自己的配料 / 做法候选**（`sku_options[].ingredient_options`），并对「按当前选择下单实际会生效」的项标 `selected: true`。只读、不改任何状态，与 `preview_order` 解耦。**一次调用里的所有商品必须属于同一个 `cart_id`**（多个店铺 / 购物车请分别调用）。

典型场景：

- **预订单阶段批量修改规格 / 配料**：`preview_order` 之后用户想给车里若干商品换杯型 / 换配料——一次调本工具拿到这些商品各自的全部规格及配料候选，换好 ID 后直接重新 `preview_order`（`quote_cart` 可选）。
- **一次查看整车多个单品的可选项**：不必逐个调用、也不必回翻整个菜单响应（编排里少接多个节点）。
- **菜单被分页 / 过滤后按单品回查**：对话上下文里菜单被挤掉时，凭 `item_id` 一次找回多个商品的全部可选项和 ID。
- **富化菜单大纲商品**：`get_shop_menu` 传 `full_menu=true` 拿到的大纲商品（无规格 / 配料、不可直接下单）——把目标 `item_id` 传入本工具即完成按需富化，返回全部规格 / 配料且同一 id 随后可直接下单。

<Note>
  **修改闭环**：本工具返回的所有 `sku_id` / `option_id` 与 `get_shop_menu` 为该 cart 生成的 ID **完全相同**（不重新生成），任意一项可直接回传 `quote_cart` / `preview_order` 修改选择；修改后重新调用 `preview_order` 获取**新的** `preview_id` + `confirmation_token` 再下单（旧令牌 10 分钟有效且一次性）。
</Note>

### 参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| `consent_grant_id` | string | 是 | — | 用户授权 ID（`cg_` 前缀，来自 `verify_user_bind`），标识已授权用户 |
| `cart_id` | string | 是 | — | 购物车上下文 ID（来自 `search_shops`）；本次所有商品都属于它 |
| `items` | array | 是 | — | 要查询的商品列表，每项一个对象，字段见下；传空数组返回 `{"items": []}` |
| `items[].item_id` | string | 是 | — | 商品 ID（来自同一 cart 的 `get_shop_menu`）|
| `items[].sku_id` | string \| null | 否 | `null` | 该商品当前选择的规格 ID，与发给 `quote_cart` / `preview_order` 的一致；不传按**默认规格**计算 |
| `items[].ingredient_option_ids` | array | 否 | `[]` | 该商品当前选择的配料选项 ID 列表，与发给 `quote_cart` / `preview_order` 的一致；不传按**默认选择**计算 |
| `items[].ingredient_quantities` | array | 否 | `[]` | 该商品当前选择的份数，与发给 `quote_cart` / `preview_order` 的一致；不传按每项 1 份计算 |
| `grouped` | boolean | 否 | `false` | 配料是否按组返回。`false` / 不传：配料平铺在 `ingredient_options` 里，每条自带 `group_name`；`true`：改为按组返回 `ingredient_groups`，组信息只出现一次 |

### 返回

顶层返回 `{ "items": [...] }`，`items` 与请求的 `items` **一一对应、顺序一致**（第 i 个结果对应第 i 个请求项）。每个结果要么是**成功项**（完整规格 / 配料候选），要么是**失败项**（`{item_id, error}`）——**靠有没有 `error` 字段区分**。

<Note>
  **部分失败不影响其余商品。** 某个商品的 `item_id` 不属于该 cart，或它的 `ingredient_option_ids` 把同一单选必选组选了两次、某个多选组选超了 `max_select`，**只有那一项**返回 `{item_id, error: {code, message}}`，其余商品照常返回，整个调用**仍算成功**（不报错）。但 `cart_id` / 授权本身无效时整次调用失败（见错误）。
</Note>

<Warning>
  所有金额字段（`price` / `original_price` / `price_delta`）单位为**分（整数）**，不是元。例如 `price: 1600` 表示 ¥16.00。
</Warning>

<Note>
  **`selected` 与 `selected_by_default` 的区别。** `selected_by_default` 是「菜单默认是哪个」；`selected` 是「这次下单实际会带哪个」，计算与下单链路同源：显式传的选项算上，没传到的**必选组自动补该组默认**；`sku_id` / `ingredient_option_ids` 都不传时即「全默认下单」会带的整套选择。因此可以直接把 `selected: true` 的项展示为「当前已选」，不会漏掉自动补齐的默认项。
</Note>

<Note>
  **配料按规格区分、随规格内嵌。** 配料与 SKU 绑定（不同杯型可选项可能不同），因此每个 `sku_options[]` 条目内嵌**该规格自己的** `ingredient_options`——换规格直接读目标规格的内嵌列表，无需再调一次。`selected: true` 只会出现在**选中规格**（`sku_options[].selected: true`）的配料候选里；其余规格的候选只标 `selected_by_default` / `available`（那个规格不会随单，故一律 `selected: false`）。**无规格商品**（`sku_options` 为空数组）的配料候选放在该结果项的顶层 `ingredient_options` 字段，仅此时出现。
</Note>

<Note>
  **选项之间可能互相排斥，候选会跟着当前选择收敛。** 有些商品的选项分层级——比如先选咖啡豆，再选萃取方式，能选的萃取方式只有那款咖啡豆对应的几种。**与当前选择冲突的候选不会出现在列表里**，所以列出来的都能选，不必自己推算哪些能共存。改了选择再调一次，可选集会跟着变。

  **同一组里换一项不受影响。** 单选组内换选项是正常操作：传新的 `option_id`、把同组的旧 `option_id` 去掉即可，同组其他选项始终在列。每个规格都按**它自己的**选择判定，换规格直接读目标规格的列表即可。
</Note>

<Note>
  **要逐级收敛，每次都得把当前选择回传。** 本接口按**本次传入**的 `sku_id` / `ingredient_option_ids` / `ingredient_quantities` 计算可选性，不记住上一次。选了一项就带着它重新调一次，才能看到收敛后的候选集。

  **⚠️ 同名不同项**：不同上层选择对应的选项可能重名（如 3 款咖啡豆各有一个「原萃浓缩」），**务必按 `option_id` 区分**。按名称比较会得出「换了上层选择、候选没变」的错误结论——实测换三款咖啡豆，可选萃取是三组完全不重叠的 `option_id`，而三组名字完全相同。
</Note>

<Note>
  **算价只在你自己选出互斥对时报错。** 同时传入互相排斥的两项，`quote_cart` 返回 `can_checkout: false` 并在 `blocking_reason` 里点名双方。

  但只传**一个**与默认项冲突的选项时，算价会**成功**：你显式选的那项会保留，而你**没指定**的组会被换成能与它共存的选项。要确认实际下单的组合，看 `quote_cart` / `preview_order` 的 `items[].selected_ingredients` 回显，不要假设「传什么就是什么」。
</Note>

<Note>
  **份数型选项用 `ingredient_quantities` 加份。** `max_quantity` 大于 1 的选项（如星巴克「浓缩份数」）在 App 上是加减号，可加多份，每份按 `price_delta` 加价。下单时用 `quote_cart` / `preview_order` 的 `items[].ingredient_quantities` 指定份数；不传则一律 1 份。部分商品有免费份数额度，实际差价以算价结果为准。
</Note>

**成功项字段**（与请求单个商品时的结果结构一致）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `items[].item_id` | string | 原样回传该请求项的 `item_id` |
| `items[].name` | string | 商品名称 |
| `items[].image_url` | string \| null | 商品图 URL，与 `get_shop_menu` / `quote_cart` / `preview_order` 回显同源同值；铸于该字段上线前的老购物车缓存无图时为 `null` |
| `items[].price` | integer | 商品展示价（分）；多规格商品为默认 / 起始价，各规格精确价见 `items[].sku_options[].price` |
| `items[].original_price` | integer \| null | 商品划线原价（分）；无原价活动（不打折）时为 `null` |
| `items[].available` | boolean | 商品是否有货 |
| `items[].min_purchase` | integer | 起购份数，≥ 1；`1` 表示无起购约束 |
| `items[].available_quantity` | integer \| null | 库存余量（份）：正整数=剩余可购，`0` 售罄，`null` 充足或未知；菜单快照、仅供展示参考 |
| `items[].promo_labels` | array | 折扣 / 促销标签 `[{text, sub_texts}]`，如 `[{"text": "8.52折", "sub_texts": ["限1份"]}]`；无则为空数组。**「单点不送」「限N份」这类购买限制只出现在标签文案里**，下单前建议一并展示。仅供展示，不参与价格计算 |
| `items[].sku_options` | array | 全量规格候选；单规格商品为空数组 |
| `items[].sku_options[].sku_id` | string | 规格 ID（`sku_`），可直接作为下单入参 |
| `items[].sku_options[].name` | string | 规格名（如「大杯」）|
| `items[].sku_options[].price` | integer | 该规格售价（折后现价，分）|
| `items[].sku_options[].original_price` | integer \| null | 该规格划线原价（优惠前，分）；该规格**无折扣时为 `null`**。同一商品各规格折扣可不同，请逐规格取用，勿套用 `items[].original_price` |
| `items[].sku_options[].promo_labels` | array | 该规格自己的折扣 / 促销标签 `[{text, sub_texts}]`，如 `[{"text": "9.2折", "sub_texts": ["限1份"]}]`；无则为空数组。**多规格商品请以本字段为准**——`items[].promo_labels` 是商品卡片文案，多规格时可能只写「8.59折起」这类**最低档**说法，看不出所选规格的实际折扣。仅供展示，不参与价格计算 |
| `items[].sku_options[].available` | boolean | 该规格是否可购买 |
| `items[].sku_options[].specs` | array | 规格明细 `[{name, value}]`，如 `[{"name": "杯型", "value": "大杯"}]` |
| `items[].sku_options[].selected` | boolean | 当前选择下实际生效的规格；不传 `sku_id` 时标默认规格 |
| `items[].sku_options[].ingredient_options` | array | **该规格**的全量配料 / 做法候选，字段结构见下 |
| `items[].sku_options[].ingredient_options[].option_id` | string | 选项 ID（`opt_`），可直接回传下单的 `ingredient_option_ids` |
| `items[].sku_options[].ingredient_options[].group_name` | string \| null | 选项组名（如「温度」「糖度」）|
| `items[].sku_options[].ingredient_options[].name` | string | 选项名 |
| `items[].sku_options[].ingredient_options[].price_delta` | integer | 该选项加价（分）|
| `items[].sku_options[].ingredient_options[].selected_by_default` | boolean | 是否为菜单默认项 |
| `items[].sku_options[].ingredient_options[].available` | boolean | 该选项是否可选。**列表里只会出现当前选择下能选的项**，所以正常都是 `true`；`false` 表示该选项售罄或已下架 |
| `items[].sku_options[].ingredient_options[].unavailable_reason` | string \| null | 不可选的原因；当前恒为 `null` |
| `items[].sku_options[].ingredient_options[].max_quantity` | integer | 该选项最多可加几份；`1` 表示只能选、不能加份。**同组各选项的上限可能不同**，按每个选项自己的值为准 |
| `items[].sku_options[].ingredient_options[].default_quantity` | integer | 商家推荐份数，仅供展示；不传 `ingredient_quantities` 时按 **1 份**下单 |
| `items[].sku_options[].ingredient_options[].required` | boolean | 该选项所在的组是否必选；必选组你没选时会自动补上该组默认项 |
| `items[].sku_options[].ingredient_options[].multi_select` | boolean | 该组能否同时选多项；`false` 时同组只能选一项，选两项会下单失败 |
| `items[].sku_options[].ingredient_options[].max_select` | integer \| null | 该组最多可选几**种**（不是几份，份数看 `max_quantity`）；单选组为 `1`，`null` 表示不限种类。超过会下单失败 |
| `items[].sku_options[].ingredient_options[].selected` | boolean | 按当前选择下单实际会带上的项；仅选中规格的候选可能为 `true` |
| `items[].ingredient_options` | array | **仅无规格商品**（`sku_options` 为空）返回：该商品唯一形态的配料候选，条目结构同上 |

**失败项字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `items[].item_id` | string | 原样回传该请求项的 `item_id` |
| `items[].error.code` | string | 错误码（如 `PUBLIC_REFERENCE_INVALID` / `CART_PRICE_INVALID`）|
| `items[].error.message` | string | 人类可读的错误说明 |


<Note>
  **`grouped=true` 时配料换一种形状返回。** 传 `grouped=true` 后，配料不再是平铺的 `ingredient_options`，而是按组返回 `ingredient_groups`：组信息（`group_name` / `required` / `multi_select` / `max_select`）只出现在组上一次，不再逐条重复；选项本身放在 `options[]` 里，字段与平铺形式逐字段一致。两种形式**二选一，不会同时出现**，内容完全相同。

  ```json
  "ingredient_groups": [
    {"group_name": "温度", "required": true, "multi_select": false, "max_select": 1,
     "options": [
       {"option_id": "opt_1", "name": "冰", "price_delta": 0, "selected_by_default": true, "max_quantity": 1, "default_quantity": 1, "available": true},
       {"option_id": "opt_2", "name": "热", "price_delta": 0, "selected_by_default": false, "max_quantity": 1, "default_quantity": 1, "available": true}
     ]},
    {"group_name": "加料", "required": false, "multi_select": true, "max_select": 5,
     "options": [
       {"option_id": "opt_5", "name": "珍珠", "price_delta": 200, "selected_by_default": false, "max_quantity": 3, "default_quantity": 1, "available": true}
     ]}
  ]
  ```
</Note>

### 错误

| 场景 | 表现 |
|------|------|
| 某个商品的 `item_id` 不属于该 `cart_id` | **该项**返回 `{item_id, error}`（`PUBLIC_REFERENCE_INVALID`），不影响其余商品 |
| 某个商品同一单选必选组传入两个选项，或某个多选组选超 `max_select` | **该项**返回 `{item_id, error}`（`CART_PRICE_INVALID`，与 `quote_cart` / `preview_order` 同款校验），不影响其余商品 |
| `cart_id` 不存在 / 已过期，或授权无效 | **整次调用失败** HTTP 400 `PUBLIC_REFERENCE_INVALID` |

### 示例

请求（用户已在 preview 选了大杯，想看这个商品以及另一个商品还能换什么）：

```json
{
  "name": "get_item_options",
  "arguments": {
    "consent_grant_id": "<consent_grant_id>",
    "cart_id": "<cart_id>",
    "items": [
      {"item_id": "<item_id_1>", "sku_id": "<当前选择的 sku_id>", "ingredient_option_ids": ["<当前选择的 option_id>"]},
      {"item_id": "<item_id_2>"}
    ]
  }
}
```
