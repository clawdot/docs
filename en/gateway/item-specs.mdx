## Overview

Food delivery item customization is divided into three layers:

| Layer | English | Example | Purpose |
|---|---|---|---|
| Specs | specs | Large / Medium / Small cup | Base options affecting price |
| Attributes | attrs | Iced / Hot / Room Temperature | Preference options not affecting price |
| Ingredients | ingredients | Add extra shot / Swap oat milk | Can affect price, have exclusion rules |

## Specs — Specifications

Each item may have one or multiple specification dimensions:

```json
{
  "specs": [
    {
      "name": "Specification",
      "options": ["Large cup", "Medium cup", "Small cup"]
    }
  ]
}
```

Selecting different specs changes the `item_id` and `sku_id`. Just pass the corresponding spec ID when ordering.

## Attrs — Attributes

Customization options not affecting price:

```json
{
  "attrs": [
    {
      "name": "Temperature",
      "options": ["Iced", "Hot"]
    },
    {
      "name": "Sweetness",
      "options": ["Normal", "Half sweet", "Less sweet", "No sugar"]
    }
  ]
}
```

## Ingredients — Extra Ingredients

<Warning>
  **Ingredients are per-SKU.** For one item, different SKUs (e.g. cup sizes) can offer different ingredients and different internal IDs — e.g. an item's "Extra Large" may only allow "Iced" while "Venti" only allows "Hot". The top-level `ingredient_options` from `get_shop_menu` is the **default SKU**'s; for any other SKU, use the `option_id`s under that SKU's `sku_options[].ingredient_options` (see [Menu API](/en/mcp/shops/detail)). If you reuse a default-SKU `option_id` on another SKU, the gateway maps it by (group name + option name); an ingredient absent on the chosen SKU is rejected at `quote_cart` / `preview_order`.
</Warning>

Most complex customization layer, including **exclusion rules**:

```json
{
  "ingredients": [
    {
      "group_name": "Shot",
      "required": true,
      "options": [
        {
          "id": "ig_0_0",
          "name": "Standard Shot",
          "price": 0.0,
          "item_id": "11111",
          "sku_id": "22222",
          "package_id": "33333"
        },
        {
          "id": "ig_0_1",
          "name": "Double Shot",
          "price": 2.0,
          "item_id": "11112",
          "sku_id": "22223",
          "package_id": "33334",
          "excludes": ["ig_1_0", "ig_1_1"]
        }
      ],
      "default_id": "ig_0_0"
    },
    {
      "group_name": "Extraction Method",
      "required": false,
      "options": [
        {
          "id": "ig_1_0",
          "name": "Hot Brew",
          "price": 0.0,
          "item_id": "21111",
          "sku_id": "32222",
          "package_id": "43333"
        },
        {
          "id": "ig_1_1",
          "name": "Cold Brew",
          "price": 3.0,
          "item_id": "21112",
          "sku_id": "32223",
          "package_id": "43334"
        }
      ],
      "default_id": "ig_1_0"
    }
  ]
}
```

### Exclusion Rules

Each option's `excludes` array lists which option IDs are **incompatible** with it:

```
Select "Double Shot" (ig_0_1) → excludes: ["ig_1_0", "ig_1_1"]
→ All options in "Extraction Method" group are excluded
→ That group becomes unselectable
```

ID format is `ig_{group_index}_{option_index}`, stable and predictable.

<Warning>
  Exclusion rules are **one-way**: A excluding B doesn't mean B excludes A. Need to check each selected option's exclusion list individually.
</Warning>

### Typical Scenarios

**Starbucks Chain Exclusion:**
```
Shot → Extraction Method → Quantity
Select "Double Shot" excludes entire "Extraction Method" group
Options in "Extraction Method" may further exclude certain "Quantity" options
```

**Mutual Exclusion:**
```
Swap Sugar ↔ Sweetness
Select "Swap Sugar" excludes all sweetness options
Select any sweetness excludes "Swap Sugar" option
```

## Default Ingredients — Defaults

For AI Agent quick ordering convenience, menu returns pre-computed `default_ingredients`:

```json
{
  "default_ingredients": [
    {
      "item_id": "11111",
      "sku_id": "22222",
      "package_id": "33333",
      "buy_amount": 1
    }
  ]
}
```

This is the result of system automatically selecting the first non-conflicting option from each required group. Agent can directly pass this field to order endpoint without understanding exclusion logic.

<Tip>
  For most ordering scenarios, directly using `default_ingredients` is the simplest approach. Only need manual selection when user explicitly requests customization.
</Tip>

## Two layers of "required groups"

"Required" appears at two distinct layers in a menu — don't conflate them:

- **Per-item required ingredient groups**: within one item you must pick enough options, e.g. a drink's required "Temperature" / "Sugar". These live in that item's `ingredient_options` (upstream `isRequired` groups). Missing one is rejected at order time as "ingredients not fully selected".
- **Store-level required item groups**: the whole order must include another item of a certain kind, e.g. a malatang shop's "Required Soup". These live in the top-level `required_groups[]` of the `get_shop_menu` response (and `categories[].required`); pick from `candidate_item_ids` and add to `items[]`.

<Note>
  The two are enforced at different times: store-level required groups are checked by the gateway at `quote_cart` (`can_checkout=false` + `blocking_reason`, a soft hint) and `preview_order` (`MISSING_REQUIRED_SELECTION`, HTTP 400 hard block); per-item required ingredient groups are validated by the upstream at order time.
</Note>

## Echoing selected specs

`get_shop_menu` returns the **available** options; `quote_cart` and `preview_order` **echo back the user's selected** specs and ingredients on each item, so you can show "what was ordered":

| Field | Description |
|-------|-------------|
| `items[].specs` | Selected specs, `[{name, value}]`, e.g. `[{"name":"Size","value":"Large"}]` |
| `items[].selected_ingredients` | Selected ingredients / options, `[{group_name, name, price_delta}]`, e.g. `[{"group_name":"Add-ons","name":"Boba","price_delta":200}]`; `group_name` may be `null`, `price_delta` is the surcharge (cents) |

The echo is translated by **each item's own `sku_id` / `ingredient_option_ids`**, so multiple items (including the same item with different specs) never cross-contaminate; fields are `[]` when there are no specs / ingredients.
