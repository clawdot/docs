## POST /shops/search

Searches or browses shops near the delivery location. Each result carries a `shop_id` and a `cart_id`: the `cart_id` encapsulates the shop and the delivery coordinates, and is the entry point for the subsequent `/shops/menu`, `/cart/quote`, and `/orders/preview` calls.

<Note>
  **Order flow**: **`/shops/search`** → `shop_id` + `cart_id` (carries delivery coordinates) → `/shops/menu` to pick items → `/cart/quote` to price the cart and get `quote_id` → `/addresses/select` to get `address_id` → `/orders/preview` → `preview_id` + `confirmation_token` → `/orders/create`. Pass the `shop_id` / `cart_id` to downstream calls as-is; do not synthesize them.
</Note>

**Two modes (switched by `keyword`):**

- **Omit / empty `keyword`** → browse mode: a nearby shop feed (up to 20) with decision fields — distance, rating, delivery fee, minimum order amount, and availability.
- **Provide `keyword`** → precise search (~5 shops): `keyword` may be a shop name ("瑞幸咖啡"), a category ("奶茶"), or a concrete item name ("生椰拿铁"); the upstream search matches at the item level, so an item keyword returns the shops that actually carry it. Each shop includes `matched_items` (display-only previews of the matched items). Note: in this mode distance / delivery_fee fields are usually `null` (upstream limitation; `rating` may carry a value depending on the upstream).

<Note>
  **Browse pagination**: in browse mode (no `keyword`), pass `offset` to page through results — send `offset: 0` on the first call, then the response's `next_offset` on each subsequent call, until `shops` comes back empty (end reached). Page size is fixed and not adjustable (it only caps how many shops one page may return). Keyword search does not support pagination.
</Note>

### Request Headers

| Name | Required | Description |
|------|----------|-------------|
| `Authorization` | Yes | `Bearer clw_...` (the Agent's API Key) |
| `X-Consent-Grant-Id` | Yes | User consent grant ID (`cg_...`) |
| `Content-Type` | Yes | `application/json` |

### Request Body

```json
{
  "keyword": "生椰拿铁",
  "address_id": "<from /addresses/select>",
  "lat": 31.23,
  "lng": 121.47,
  "city": "上海"
}
```

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `keyword` | string | No | `null` | Keyword: shop name / category / item name. Omit or leave blank for browse mode |
| `address_id` | string | No | `null` | Gateway address ID (from `/addresses/select`); resolves the delivery location, takes priority over `lat`/`lng` |
| `lat` | float | No | `null` | Latitude (GCJ-02) |
| `lng` | float | No | `null` | Longitude (GCJ-02) |
| `city` | string | No | `null` | City name to scope the search |
| `offset` | integer | No | `null` | **Browse mode only**: pagination cursor. Omit = first page (same as legacy); pass the previous response's `next_offset` to fetch the next page. Page size is fixed and not adjustable. Ignored when `keyword` is set |

<Note>
  **How the delivery location is resolved**: in order, ① the coordinates of the saved address behind `address_id` → ② the `lat`/`lng` passed explicitly → ③ the user's most-recently-used saved address / remembered location. If none resolve, the call returns `COORDS_REQUIRED`. So `address_id` and `lat`/`lng` are both optional, but at least one location source must be resolvable.
</Note>

### Response

```json
{
  "shops": [
    {
      "shop_id": "shop_4f2a...",
      "cart_id": "cart_9b3e...",
      "name": "瑞幸咖啡(人民广场店)",
      "brand_name": "瑞幸咖啡",
      "logo_url": "https://image.url/shop.jpg",
      "distance_text": "1.2km",
      "delivery_time_text": "35分钟",
      "delivery_fee_text": "配送 ¥3",
      "rating": 4.8,
      "monthly_sales_text": "月售2000+",
      "min_order_amount": 0,
      "available": true,
      "unavailable_reason": null,
      "matched_items": [
        {
          "name": "生椰拿铁",
          "description": "椰浆+浓缩咖啡",
          "price": 1600,
          "original_price": 2900
        }
      ]
    }
  ],
  "next_offset": 20
}
```

<Warning>
  Amount fields are in **cents (integer)**, not yuan. e.g. `min_order_amount: 0` means ¥0, `price: 1600` means ¥16.00.
</Warning>

| Field | Type | Description |
|-------|------|-------------|
| `shops` | array | Shop list (up to 20 in browse mode, ~5 in keyword search) |
| `next_offset` | integer \| null | **Returned only when paging in browse mode** (request included `offset`): cursor for the next page, use as the next request's `offset`; empty `shops` means the end. Requests without `offset` do **not** include this field |
| `shops[].shop_id` | string | Shop ID (`shop_` prefix); pass to `/shops/menu` / `/cart/quote` / `/orders/preview` as-is |
| `shops[].cart_id` | string | Cart context ID (`cart_` prefix), carries the shop & delivery coordinates; downstream calls reuse it instead of passing lat/lng |
| `shops[].name` | string | Shop name |
| `shops[].brand_name` | string \| null | Brand name |
| `shops[].logo_url` | string \| null | Shop logo URL |
| `shops[].distance_text` | string \| null | Distance from the delivery location (text; may be `null` in keyword search mode) |
| `shops[].delivery_time_text` | string \| null | Estimated delivery text (may be `null` in keyword search mode) |
| `shops[].delivery_fee_text` | string \| null | Delivery fee text (may be `null` in keyword search mode) |
| `shops[].rating` | float \| null | Rating (may be `null` in keyword search mode) |
| `shops[].monthly_sales_text` | string \| null | Monthly sales text |
| `shops[].min_order_amount` | integer \| null | Minimum order amount (cents); `null` when absent |
| `shops[].available` | boolean | Whether orderable (open and not closed) |
| `shops[].unavailable_reason` | string \| null | Reason if unavailable |
| `shops[].matched_items` | array | Matched item previews (keyword search only; **display-only**) |
| `shops[].matched_items[].name` | string | Item name |
| `shops[].matched_items[].description` | string \| null | Item description (max 80 chars) |
| `shops[].matched_items[].price` | integer | Item price (cents) |
| `shops[].matched_items[].original_price` | integer \| null | Original price (cents) |

<Warning>
  `matched_items` carry **no IDs and no stock state**. To order, you must first call `/shops/menu` and use the `item_id` / `sku_id` / option IDs it returns; item availability is also the menu's call.
</Warning>

### Error Codes

| HTTP | code | Description |
|------|------|-------------|
| 401 | `CONSENT_GRANT_REQUIRED` | Missing `consent_grant` (no consent grant passed) |
| 401 | `CONSENT_GRANT_INVALID` | Consent grant is invalid |
| 401 | `CONSENT_GRANT_EXPIRED` | Consent grant has expired; re-authorization required |
| 403 | `CAP_NOT_BOUND` | This capability is not enabled for the Agent |
| 403 | `CONSENT_GRANT_WRONG_CAP` | Consent grant belongs to a different capability or provider |
| 400 | `PUBLIC_REFERENCE_INVALID` | `address_id` is invalid or does not belong to the consented user |
| 400 | `COORDS_REQUIRED` | Neither `address_id` nor `lat`/`lng` was given and no remembered location is available |
| 502 | `ELEME_ERROR` | Upstream search API error |

See [Error Handling](/en/gateway/error-handling) for the full list.

### Example

```bash
curl -X POST "http://eleme-gateway.hicaspian.com/api/v1/shops/search" \
  -H "Authorization: Bearer clw_your_api_key" \
  -H "X-Consent-Grant-Id: cg_your_consent_grant" \
  -H "Content-Type: application/json" \
  -d '{
    "keyword": "生椰拿铁",
    "address_id": "<from /addresses/select>"
  }'
```
