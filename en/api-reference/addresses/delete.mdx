## POST /addresses/delete

Deletes one of the user's saved addresses. Once deleted, the `address_id` is immediately invalid and no longer appears in the saved list from `/addresses/search`.

<Note>
  **Address flow**: `/addresses/search` to find a place → `suggestion_token` → `/addresses/select` to save → `address_id` → `/addresses/update` to edit → **`/addresses/delete`** to remove a saved address.
</Note>

<Note>
  **Only deletes the consenting user's own address; others are unaffected.** `address_id` is scoped to the consenting user, so a delete only removes this user's saved record. The upstream delivery address book is shared by phone number (one phone == one Eleme account); the gateway reclaims the upstream address only when **no record still references it**, so deleting never removes an upstream address that is still used elsewhere on the same account.
</Note>

<Note>
  **Does not affect placed orders.** An order records its delivery address at checkout time, so deleting a saved address only affects *future* orders that would reuse this `address_id`, not orders already submitted.
</Note>

### Request Headers

| Name | Required | Description |
|------|----------|-------------|
| `Authorization` | Yes | `Bearer clw_...` (the Agent's API Key) |
| `X-Consent-Grant-Id` | Yes | User consent grant ID (`cg_...`) |
| `Content-Type` | Yes | `application/json` |

### Request Body

```json
{
  "address_id": "<from /addresses/select>"
}
```

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `address_id` | string | Yes | — | ID of the saved address to delete; use the `address_id` returned by `/addresses/select` / `/addresses/search` as-is |

<Warning>
  The body **rejects undefined fields** (`extra=forbid`); extra fields return 422.
</Warning>

### Response

```json
{
  "address_id": "addr_7c1e...",
  "deleted": true
}
```

| Field | Type | Description |
|-------|------|-------------|
| `address_id` | string | The deleted gateway address ID (`addr_`); echoes the input |
| `deleted` | boolean | Always `true` on success |

### Error Codes

| HTTP | code | Description |
|------|------|-------------|
| 401 | `CONSENT_GRANT_REQUIRED` | Missing `X-Consent-Grant-Id` |
| 401 | `CONSENT_GRANT_INVALID` | Consent grant ID is invalid |
| 401 | `CONSENT_GRANT_EXPIRED` | Consent grant has expired; re-authorization required |
| 403 | `CAP_NOT_BOUND` | The delivery capability is not enabled for this Agent |
| 403 | `CONSENT_GRANT_WRONG_CAP` | The consent grant belongs to a different capability / provider |
| 400 | `PUBLIC_REFERENCE_INVALID` | `address_id` is invalid, expired, not owned by the consenting user, or already deleted |

<Note>
  A public-endpoint `address_id` is always resolved through the public-reference layer first, which returns 400 `PUBLIC_REFERENCE_INVALID` when the address is missing, not owned by the consenting user, or already deleted. 404 `ADDRESS_NOT_FOUND` is only reachable under an extreme concurrent race (the row is deleted by another request after resolution passes but before the internal delete), so a normal call will never see it.
</Note>

See [Error Handling](/en/gateway/error-handling) for the full list.

### Example

```bash
curl -X POST "https://eleme-gateway.hicaspian.com/api/v1/addresses/delete" \
  -H "Authorization: Bearer clw_your_api_key" \
  -H "X-Consent-Grant-Id: cg_your_consent_grant" \
  -H "Content-Type: application/json" \
  -d '{
    "address_id": "<from /addresses/select>"
  }'
```
