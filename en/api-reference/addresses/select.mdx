## POST /addresses/select

Materializes an address search suggestion (`suggestion_token`) together with recipient details into a gateway address, or re-selects an already-saved address (`address_id`), and returns the gateway address ID `address_id` for use by `/shops/search`, `/orders/preview`, etc.

<Note>
  **Address flow**: `/addresses/search` → suggestion `token` → **`/addresses/select`** (with `token` + recipient) → `address_id` → used by `/shops/search` (location) / `/orders/preview` (ordering). The `address_id` is issued by the gateway and passed back as-is; do not fabricate it.
</Note>

<Note>
  **Two modes (pick one)**:
  - **Create**: pass `suggestion_token` (the `token` from `/addresses/search`) + `contact_name` + `contact_phone` + `address_detail`; the gateway registers a new delivery address upstream and persists it.
  - **Re-select**: pass an existing `address_id` to fetch that address back (still send `contact_name` / `contact_phone`, but the saved record is not modified).

  Sending neither returns `PUBLIC_REFERENCE_INVALID`.
</Note>

### Request Headers

| Name | Required | Description |
|------|----------|-------------|
| `Authorization` | Yes | `Bearer clw_...` (the Agent's API Key) |
| `X-Consent-Grant-Id` | Yes | User consent grant ID (`cg_...`) |
| `Content-Type` | Yes | `application/json` |

### Request Body

```json
{
  "suggestion_token": "<token from /addresses/search>",
  "address_id": null,
  "contact_name": "Zhang San",
  "contact_phone": "13800138000",
  "address_detail": "Building 3, Room 101"
}
```

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `suggestion_token` | string \| null | No | `null` | Address suggestion token (the `token` returned by `/addresses/search`); required when creating a new address |
| `address_id` | string \| null | No | `null` | Saved gateway address ID (from a previous `/addresses/select`); pass this to re-select a saved address. Mutually exclusive with `suggestion_token`; sending neither is an error |
| `contact_name` | string | Yes | — | Recipient name |
| `contact_phone` | string | Yes | — | Recipient phone number |
| `address_detail` | string | No | `""` | Apartment / floor / room number. **Must be non-empty** when creating a new POI address (upstream rejects blank detail), otherwise returns `DETAIL_REQUIRED` |

### Response

```json
{
  "address_id": "addr_8c1f...",
  "display_name": "People's Square, Huangpu District, Shanghai",
  "address_detail": "Building 3, Room 101",
  "city": "",
  "lat": 31.2304,
  "lng": 121.4737,
  "contact_name": "Zhang San",
  "contact_phone_masked": "138****8000"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `address_id` | string | **Gateway address ID (`addr_` prefix, string)**; pass it as-is to `/shops/search`, `/orders/preview`, etc. Stays the same on re-select |
| `display_name` | string | Address display name (the POI name chosen in the suggestion) |
| `address_detail` | string | Apartment / floor / room number |
| `city` | string | City (always an empty string when re-selecting a saved address) |
| `lat` | number \| null | Latitude |
| `lng` | number \| null | Longitude |
| `contact_name` | string \| null | Recipient name |
| `contact_phone_masked` | string | Masked recipient phone (middle four digits masked, e.g. `138****8000`); the full number is never returned. Strictly `string \| null` (empty number → `null`, fewer than 7 digits → `***`), but a saved address always has a phone, so in practice it is always a non-empty masked string |

### Error Codes

| HTTP | code | Description |
|------|------|-------------|
| 401 | `CONSENT_GRANT_REQUIRED` | Missing consent grant (no `X-Consent-Grant-Id`) |
| 401 | `CONSENT_GRANT_INVALID` | Consent grant is invalid |
| 401 | `CONSENT_GRANT_EXPIRED` | Consent grant has expired; re-authorization required |
| 403 | `CAP_NOT_BOUND` | The delivery capability is not enabled for this agent |
| 403 | `CONSENT_GRANT_WRONG_CAP` | Consent grant belongs to a different capability / provider |
| 400 | `PUBLIC_REFERENCE_INVALID` | `address_id` is invalid / not owned by the consenting user, or neither `suggestion_token` nor `address_id` was provided |
| 400 | `SUGGESTION_EXPIRED` | `suggestion_token` is invalid or expired; re-run `/addresses/search` |
| 400 | `CONTACT_REQUIRED` | Missing recipient name or phone |
| 400 | `DETAIL_REQUIRED` | Missing non-empty apartment / floor when creating a new POI address |
| 502 | `ELEME_ERROR` | Upstream address registration failed |

See [Error Handling](/en/gateway/error-handling) for the full list.

### Example

```bash
curl -X POST "https://eleme-gateway.hicaspian.com/api/v1/addresses/select" \
  -H "Authorization: Bearer clw_your_api_key" \
  -H "X-Consent-Grant-Id: cg_your_consent_grant" \
  -H "Content-Type: application/json" \
  -d '{
    "suggestion_token": "<token from /addresses/search>",
    "contact_name": "Zhang San",
    "contact_phone": "13800138000",
    "address_detail": "Building 3, Room 101"
  }'
```
