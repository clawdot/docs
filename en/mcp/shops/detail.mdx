## get_shop_menu

Fetches a shop's menu. Each returned item carries a gateway-minted `item_id` (plus optional `sku_id` / `option_id`); these IDs are the only valid order references for the downstream `quote_cart`, `preview_order`, and `create_order` calls. Menus can be large (100+ items), so it supports `keyword` filtering and `limit` / `offset` paging (progressive disclosure).

<Note>
  **Order flow**: `search_shops` → `shop_id` + `cart_id` (carries delivery coordinates) → **`get_shop_menu`** to pick items and get `item_id` / `sku_id` → `quote_cart` to price and get `quote_id` → `select_address` to get `address_id` → `preview_order` → `preview_id` + `confirmation_token` → `create_order`. The menu must be based on an existing `cart_id`, and `shop_id` must match that `cart_id` (both returned by the same `search_shops`).
</Note>

### Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `consent_grant_id` | string | Yes | — | User consent grant ID (`cg_` prefix, from `verify_user_bind`), identifying the consenting user |
| `shop_id` | string | Yes | — | Shop ID (from `search_shops`), passed back as-is |
| `cart_id` | string | Yes | — | Cart context ID (from `search_shops`; carries shop & delivery coordinates) |
| `address_id` | string \| null | No | `null` | Gateway address ID (from `select_address`); when provided, its coordinates resolve the delivery location |
| `lat` | float \| null | No | `null` | Delivery latitude; falls back to the coordinates carried by `cart_id` when omitted |
| `lng` | float \| null | No | `null` | Delivery longitude; falls back to the coordinates carried by `cart_id` when omitted |
| `keyword` | string \| null | No | `null` | Keyword filter, matched against item name / category / description (case-insensitive) |
| `limit` | integer \| null | No | `null` | Items per page, ≥ 1; returns all (filtered) items when omitted |
| `offset` | integer | No | `0` | Paging offset, ≥ 0; pair with the previous response's `next_offset` to page |

<Note>
  `address_id` / `lat` / `lng` resolve the delivery coordinates and are usually unnecessary: the `cart_id` already carries the coordinates from search. When all three are omitted, the `cart_id` coordinates are used.
</Note>

### Returns

<Warning>
  All amount fields (`price` / `original_price` / `price_delta`) are in **cents (integer)**, not yuan. e.g. `price: 1600` means ¥16.00.
</Warning>

<Note>
  **Ingredients are per-SKU.** Ingredients are bound to a specific SKU — which ingredients are available, and their internal IDs, can differ per SKU (e.g. cup size). The top-level `items[].ingredient_options` belongs to the **default SKU**; for any other SKU, use the `option_id`s under that SKU's `items[].sku_options[].ingredient_options`. If you reuse a default-SKU `option_id` on a non-default SKU, the gateway maps it to that SKU's matching ingredient by (group name + option name); an ingredient that doesn't exist on the chosen SKU is rejected at `quote_cart` / `preview_order` (not at `create_order`).
</Note>

<Note>
  **Store-level required item groups.** Some shops (malatang, certain combo shops) require the whole order to include an item of a certain kind — e.g. a malatang shop's "Required Soup"; without a soup the upstream rejects the order. This constraint is exposed via `required_groups`: before ordering you must pick at least `min_select` item(s) from each `required_groups[].candidate_item_ids` and add them as normal entries to `items[]` (candidate details are in `required_groups[].candidates` — with name/price/available, always complete; with `keyword` or paging the required candidates may not appear in the current page's `items[]`). When unmet, `quote_cart` returns `can_checkout=false` + `blocking_reason`, and `preview_order` returns `MISSING_REQUIRED_SELECTION` (HTTP 400). This is a different layer from a product's **required ingredient groups** (the required option groups inside `ingredient_options`, e.g. a drink's required temperature / sugar): the former is "must add another item", the latter is "must pick enough options inside one item".
</Note>

| Field | Type | Description |
|-------|------|-------------|
| `shop.shop_id` | string | Shop ID (echoes the request `shop_id`) |
| `shop.cart_id` | string | Cart context ID (echoes the request `cart_id`) |
| `shop.name` | string | Shop name |
| `shop.logo_url` | string \| null | Shop logo URL, same source as `shops[].logo_url` from `search_shops` (the menu upstream returns no logo; the value comes from the context saved with the `cart_id` at search time); `null` for a `cart_id` minted before this field shipped |
| `shop.min_order_amount` | integer \| null | Minimum order amount in **cents**, same value as `shops[].min_order_amount` from `search_shops` (the menu upstream returns no minimum; the value is the snapshot saved with the `cart_id` at search time) — use it to tell whether the cart clears the shop's minimum; `null` for a `cart_id` minted before this field shipped |
| `shop.available` | boolean | Whether the shop is orderable (currently always `true`) |
| `categories` | array | Lightweight index of this page's items by category |

| `categories[].items` | array | Items in this category with card essentials: `item_id`/`name`/`price`/`available`/`image_url` — clients can render category nav + card pages directly from categories; specs are looked up locally in this response's `items[]` by `item_id` |
| `categories[].required` | boolean | Whether this category is a store-level required group (returned for required categories only) |
| `categories[].min_select` | integer | Minimum items to pick from a required category (returned for required categories only) |
| `items` | array | Full item list for this page (see below) |
| `items[].item_id` | string | Item ID (`item_`), **required to order**; pass as `items[].item_id` to `quote_cart` and `preview_order` |
| `items[].name` | string | Item name |
| `items[].category_name` | string \| null | Category this item belongs to |
| `items[].description` | string \| null | Item description |
| `items[].image_url` | string \| null | Item image URL |
| `items[].price` | integer | Current price (cents) |
| `items[].original_price` | integer \| null | Original price (cents); `null` when not discounted |
| `items[].tip_texts` | array | Ready-made marketing copy from upstream (e.g. `["月售 1000+", "好评率 100%"]` — monthly sales / positive-rating rate); `[]` when absent. Display-only, not an order input |
| `items[].promo_labels` | array | Discount/promo labels with main/sub structure; `[]` when absent. May also carry delivery-restriction labels (e.g. "单点不送" = cannot be ordered alone; prompt the user to pair it with a regular item, otherwise `quote_cart` returns `blocking_code=1`) |
| `items[].promo_labels[].text` | string | Main label text (e.g. "66折" = 34% off) |
| `items[].promo_labels[].sub_texts` | array | Sub label texts (e.g. `["限3份"]` = limit 3) |
| `items[].recommend_reasons` | array | Recommendation copy (e.g. `["7天内15人下单"]` = 15 orders in 7 days); `[]` when absent. Display-only |
| `items[].available` | boolean | Whether in stock |
| `items[].unavailable_reason` | string \| null | Reason if unavailable; `"sold_out"` when out of stock, otherwise `null` |
| `items[].min_purchase` | integer | Minimum purchase quantity, ≥ 1; `1` means no minimum. If `quantity` is below it, `quote_cart` returns `can_checkout=false` and `preview_order` fails with `BELOW_MIN_PURCHASE` |
| `items[].available_quantity` | integer \| null | Remaining stock (units): a positive integer is what's left to buy, `0` means sold out, `null` means ample or unknown. **A menu-time snapshot, for display only** — actual availability is enforced at order time (over-stock carts are rejected at `quote_cart` / `preview_order`) |
| `items[].sku_options` | array | SKU options (e.g. cup size); pass the chosen `sku_id` as `items[].sku_id` when ordering |
| `items[].sku_options[].sku_id` | string | SKU ID (`sku_`), passed back as-is to the order `sku_id` |
| `items[].sku_options[].name` | string | SKU name (e.g. "Large") |
| `items[].sku_options[].price` | integer | Price for this SKU (cents) |
| `items[].sku_options[].available` | boolean | Whether this SKU is selectable |
| `items[].sku_options[].ingredient_options` | array | This SKU's **own** ingredient/option choices (same fields as `items[].ingredient_options`); **returned for non-default SKUs only**. Ingredients vary by SKU (e.g. different cup sizes allow different "temperature"); use these `option_id`s when ordering this SKU. |
| `items[].ingredient_options` | array | Ingredient / option choices (e.g. temperature, sugar) for the **default SKU**; for other SKUs see `items[].sku_options[].ingredient_options` |
| `items[].ingredient_options[].option_id` | string | Option ID (`opt_`), passed back as-is to the order `items[].ingredient_option_ids` |
| `items[].ingredient_options[].group_name` | string | Option group name (e.g. "Sugar") |
| `items[].ingredient_options[].name` | string | Option name (e.g. "Standard") |
| `items[].ingredient_options[].price_delta` | integer | Surcharge for this option (cents), defaults to `0` |
| `items[].ingredient_options[].selected_by_default` | boolean | Whether this is the default option |
| `items[].ingredient_options[].available` | boolean | Whether this option is selectable |
| `total_items` | integer | Total item count after `keyword` filtering |
| `has_more` | boolean | Whether there is a next page |
| `next_offset` | integer \| null | The `offset` for the next page; `null` when `has_more` is `false` |
| `required_groups` | array | Store-level required item groups (e.g. a malatang shop's "Required Soup"); the order must include at least `min_select` item(s) from each group's `candidate_item_ids`. `[]` when the shop has no such constraint |
| `required_groups[].name` | string | Required-group name (e.g. "Required Soup") |
| `required_groups[].required` | boolean | Always `true` |
| `required_groups[].min_select` | integer | Minimum items to pick from this group (currently always `1`) |
| `required_groups[].candidate_item_ids` | array | `item_id`s of candidate items; pick at least `min_select` of them and add as normal items to the order `items[]` |
| `required_groups[].candidates` | array | Candidate details `[{item_id, name, price, available}]`, one-to-one with `candidate_item_ids` and **always complete** (decoupled from `keyword`/paging); agent renders candidates directly without re-checking `items[]` |

<Tip>
  **Progressive disclosure**: use `keyword` to narrow results, or `limit` + `offset` to page. While `has_more` is `true`, keep calling with `offset=next_offset` until `has_more` is `false`. Item IDs returned by earlier calls on the same `cart_id` stay orderable for the cart's lifetime.
</Tip>

### Error Codes

| code | Description |
|------|-------------|
| `CONSENT_GRANT_REQUIRED` | Missing consent grant (no `consent_grant_id`) |
| `CONSENT_GRANT_INVALID` | Consent grant is invalid |
| `CONSENT_GRANT_EXPIRED` | Consent grant has expired; re-authorization required |
| `CAP_NOT_BOUND` | The delivery capability is not enabled for this agent |
| `CONSENT_GRANT_WRONG_CAP` | Consent grant belongs to a different capability / provider |
| `PUBLIC_REFERENCE_INVALID` | `cart_id` invalid or expired, `shop_id` invalid, or `shop_id` and `cart_id` mismatch |
| `ELEME_ERROR` | Upstream menu fetch failed |

See [Error Handling](/en/gateway/error-handling) for the full list.

### Example Call

```json
{
  "name": "get_shop_menu",
  "arguments": {
    "consent_grant_id": "cg_your_consent_grant",
    "shop_id": "<from search_shops>",
    "cart_id": "<from search_shops>",
    "keyword": "latte",
    "limit": 20,
    "offset": 0
  }
}
```
