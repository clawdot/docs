## revoke_user_bind

Revokes the current user's authorization: clears the credential on the binding row so the `consent_grant_id` used for this call is invalidated immediately on both the REST and MCP surfaces. The Agent's credential is unaffected. Maps to the REST endpoint `POST /auth/unbind`.

<Note>
  **Authorization flow**: `request_user_bind` → `verify_user_bind` to get `consent_grant_id` → business calls → **`revoke_user_bind`** to revoke. After revocation the `consent_grant_id` is invalid immediately; to act for this user again, run the bind flow (`request_user_bind` + `verify_user_bind`) to mint a NEW `consent_grant_id`. The user's saved addresses and order history are kept and become reachable again after re-binding the same phone number.
</Note>

### Parameters

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `consent_grant_id` | string | Yes | User consent grant ID (`cg_...`); this is the grant being revoked |

### Returns

| Field | Type | Description |
|-------|------|-------------|
| `revoked` | boolean | Whether the grant was revoked; always `true` |
| `next_action` | string | Suggested next action, always `request_user_bind` (start the bind flow again) |

### Error Codes

| code | Description |
|------|-------------|
| `AUTH_REQUIRED` | Missing Agent authentication |
| `AUTH_INVALID` | Agent credential invalid or disabled |
| `CONSENT_GRANT_REQUIRED` | Missing `consent_grant_id` |
| `CONSENT_GRANT_INVALID` | `consent_grant_id` invalid or no longer valid (e.g. already revoked) |
| `CONSENT_GRANT_EXPIRED` | User consent grant has expired |
| `CAP_NOT_BOUND` | The Agent has not been granted this capability |
| `CONSENT_GRANT_WRONG_CAP` | The grant belongs to a different capability / provider |

See [Error Handling](/en/gateway/error-handling) for the full list.

### Example Call

```json
{
  "name": "revoke_user_bind",
  "arguments": {
    "consent_grant_id": "cg_your_consent_grant"
  }
}
```
