## What are Skills?

Clawdot aggregates downstream delivery platforms (Ele.me, Meituan, etc.), local-life platforms (Amap, etc.), and merchants' own Agent service capabilities. On top of these, Clawdot defines a **standardized service SOP and interface protocol**—a unified flow for menu lookup, order fulfillment, address management, order tracking, and more.

**Skills** are the **Agent-facing skill packs** packaged on top of this standard. Each Skill is an independent, installable capability unit; once an Agent installs it, the Agent gains the corresponding local-life service capability.

## Design approach

Skills follow a three-layer separation principle:

**Layer 1: Platform capability aggregation.** Clawdot integrates the APIs of multiple delivery and local-life platforms and consolidates their capabilities. Merchants don't need to change anything—Clawdot's Proxy layer handles format conversion and protocol adaptation. Large chain brands can also build their own Agent that implements the standard protocol directly.

**Layer 2: Standardized protocol and SOP.** On top of platform capabilities, Clawdot defines a unified interface spec and interaction flow. No matter whether the backend is Ele.me or Meituan, the Agent on top uses the same standard chain: `search_shops` (search) → `get_shop_menu` (menu) → `quote_cart` (quote) → `select_address` (address) → `preview_order` (preview) → `create_order` (order) → `get_sign_action` (passwordless signing). The complex customization system for item specs, attributes (attrs), and ingredients is also unified into standard data structures. All amount fields are in **cents (integers)**. See the full chain in [Order Flow](/en/gateway/order-flow).

**Layer 3: Skill packaging.** Based on the standardized protocol and SOP, Clawdot packages each category of service into an independent Skill. Each Skill contains a complete interaction guide (GUIDE), action definitions (Actions), and a platform adaptation layer (Platforms), so the Agent works out of the box once installed.

## Anatomy of a Skill

Each Skill is a standardized pack containing the following parts:

| Component | Description | Example |
|---------|------|------|
| **skill.yaml** | Skill metadata: name, version, action list, environment dependencies | `name: takeout`, `actions: [search_shops, get_shop_menu, preview_order, create_order]` |
| **GUIDE.md** | Interaction SOP: how the Agent should talk to the user and when to call which action | "Do it first, then speak. State the conclusion, not the process." |
| **scripts/** | Execution scripts: the logic that actually calls the Gateway API | `takeout.py` — full implementation of search, item selection, ordering |
| **platforms/** | Platform adaptation layer: SKILL.md configs for different Agent platforms | One each for Claude Code, OpenClaw, Codex |

## Authentication model

Skills use **two-layer authentication**: an **API Key** identifies the Agent, and a **user authorization (consent grant)** identifies the authorized delivery user. The Agent holds its own API Key, then runs a binding flow per user to obtain a `consent_grant_id` (`cg_` prefix); the two together let it act on that user's behalf. Each authorization is independent and revocable at any time, naturally creating security isolation with no need for a complex permission-management system.

- **API Key (Agent identity):** passed at the connection layer via the `Authorization: Bearer clw_...` header; generated when you create an Agent in the [console](https://console.hicaspian.com/agents).
- **User authorization (consent grant):** passed as each MCP tool's `consent_grant_id` parameter (`cg_` prefix, not a header).

Suitable for: personal assistants, desktop Agents (Claude Desktop, Cursor, etc.), and various Agent-platform integrations. See [Authentication](/en/gateway/authentication) for full details.

## Supported platforms

The Skill platform adaptation layer lets the same Skill run across multiple Agent environments:

| Platform | Integration | Use case |
|------|---------|---------|
| **Claude Code** | Python scripts + SKILL.md instructions | Desktop developers, personal Agents |
| **OpenClaw** | Tool SDK + camelCase parameters | Open-platform integration |
| **Codex** | Python scripts + AGENTS.md | OpenAI Codex Agent |
| **Self-built Agent** | Connect directly to the MCP tool contract | DingTalk, Kimi, QCloud, any platform |
