## What is the Skills Platform?

The Skills Platform is Layer 2 in the Clawdot core architecture, serving as the integration hub for **restricted skills (one-to-one)** for every AI Agent. Unlike generic gateways designed for super apps, the Skills Platform focuses on **private, personalized** Agent access—each Agent is bound to its corresponding user, naturally creating security isolation.

Through the Skills Platform, any AI Agent can:
- Access local life services (food delivery, supermarkets, restaurants, etc.)
- Safely manage user identity and transaction data
- Connect with the rich skill library in the Gateway layer
- Build end-to-end local life application experiences

## Core Features

<CardGroup cols={2}>
  <Card title="One-to-One Binding Authorization" icon="lock">
    Each Agent and its user form a 1:1 binding relationship, ensuring data isolation and security. No need for complex permission management systems—natural security isolation is built-in.
  </Card>

  <Card title="Multi-Platform Support" icon="share-nodes">
    Native support for DingTalk, Kimi, QCloud, Claude Desktop (MCP), Cursor, and other mainstream Agent platforms, easily extensible for personal Agents.
  </Card>

  <Card title="Gateway Skill Reuse" icon="puzzle-piece">
    Directly inherit the local life skills library from the Gateway layer—no need to redevelop, skills are abstracted and pushed down to the Skills Platform.
  </Card>

  <Card title="Simplified Integration" icon="rocket">
    Three integration methods (MCP, REST API, OpenAI Function Calling) lower the barrier to entry, supporting rapid prototyping and production deployment.
  </Card>
</CardGroup>

## Skills vs Super Agent

| Feature | Skills Platform | Super Agent |
|---------|-----------------|------------|
| **Skill Scope** | Restricted skills (curated, safe) | Full-featured skills (complete) |
| **User Binding** | One-to-one (single user) | One-to-many (multiple users) |
| **Use Cases** | Personal Agents, private apps | Public accounts, platform apps |
| **Security Isolation** | Natural isolation (technically guaranteed) | Requires permission management (complex) |
| **Integration Complexity** | Very low (API Key + User Token) | Medium (authorization flow) |
